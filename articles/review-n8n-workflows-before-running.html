Review an n8n workflow before you run it

Inspect every workflow trigger and node, follow the path of credentials and data, then test with fictional inputs before enabling it.

By Ayoub YatoujiPublished November 27, 2026Updated November 27, 20262 min read

Information last checked: November 27, 2026

This checklist is general guidance, not a security certification. n8n documentation and version-specific controls may change.

A workflow export is executable configuration, not just a diagram. Before importing or activating one, understand what starts it, which nodes run, where data goes, and what changes the workflow can make.

Inspect the full execution path

  • Identify manual, schedule, webhook, and event triggers.
  • Review every HTTP request and the destination it contacts.
  • Check file, shell, database, and write operations for their side effects.
  • Trace which fields are passed to each external service.
  • Confirm that credentials are referenced through the platform's credential manager, not embedded in exported JSON.

Test with minimal, fictional data

Keep the workflow inactive while reviewing it. Run a small manual test with fictional values, inspect the output, and check error paths. Only then consider connecting authorized credentials with the narrowest appropriate permissions.

Plan ownership and failure handling

Decide who owns the workflow, how failures are noticed, how long execution data is retained, and how to disable the automation. Document external services and any user or customer data processed.

Never execute blindly

Do not run a downloaded workflow because its title or publisher looks familiar. Inspect its nodes, destinations, permissions, and version first.

A useful starter is deliberately limited

The demonstration workflows in this hub use manual triggers and Set nodes only. They do not call APIs, access a file system, or include credentials. Treat them as learning examples, not production-ready automations.
